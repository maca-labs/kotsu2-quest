# 第6章「流動の天空城」・帰りの船

第5章で「今回は運用しない」を選んだ続きから、灯台守ルカの依頼「帰りの船」を確認した。初回調査では正規のゲーム操作で第5章の推奨9件・章印・ランタン取得までを再構成した。さらに公開版の画面から第5章を完走し、設定の「JSONを書き出す」で保存した。この同じファイルを修正前と修正後の両方で通常の読込みから使い、第6章を一周した。出発時の財布は900 USDC、ハイリキは99 USDC、4つの運用ラボはすべて未受講。

## 初心者役がたどった道

幅360px、高さ780pxのChromeで、第5章の町から天空城に入り、学者の家で受注。帰り帆の洞窟まで歩き、クモツバサと戦った。練習スマホで出金と受取の26工程を終え、洞窟の出口から歩いて町に戻り、学者の家でルカに報告した。最後に「流動の古龍」の確認5題を終え、港の村長リオから「暁の冠」を受け取り、装備した。

## 第5章から運んだ教材資金

今回の送る額99から教材の出金費1を引くと、受取明細は98。財布の合計は元の900と今回の98を合わせた998。ガス用の0.0009 ETHは別に記録され、この出金の前後で数量は変わらない。行き先は自分の練習財布 `DEMO-WALLET-A`、道はArbitrum。これらはゲーム内の条件。

## 見つけて直したところ

- 最初の明細に未受講ラボの金額も並んでいた。受注した経路の台帳から今回の金額を表示し、見送りでは売却や預け先の解除が不要な理由を示した。
- ネットワークや宛先を間違えると、短い画面では訂正の文が下に隠れた。選び直す欄に矢印と訂正文を表示するようにした。
- 出金確定の近くに手数料の内訳がなく、着金を照合するときには財布の合計のほうが目立った。申請時は費用を引いた受取予定額、到着時は今回の受取額と財布の合計を操作のそばに置いた。
- 財布に届いた後も出金アプリを表示していた。受取通知・受取明細・残高は練習ウォレットで開くようにした。
- 帰還を報告したあとも、ルカが「町へ戻り、ルカに結果を知らせよう」と言っていた。家では受取明細に応えて報告を受け取る。長老の記録も、第5章から続けた旅と第6章だけの練習を区別する。
- 運用を見送った人の冒険の記録で「ラボ固有の解除操作」に印が付いていた。この工程で確かめたことを「出金前に売却や解除が必要かを確かめる」と表示する。運用をしていない場合もこの判断は練習できる。未受講ラボの記録は増えない。
- 古龍の試練では、ボス専用の資金と受取カードを表示する。見送りの試練の資金は100 USDC、受取先は `DEMO-RETURN-B`、教材費1を引いた受取は99。旅本編の998とは別に記録される。

## 確認方法

会計検証では本編と第6章単独開始の両方で全26工程を実行し、各工程の再実行・保存からの復帰・他ラボの台帳を点検した。単独開始では元の財布が0のため、同じ98が届いても合計は98になる。古龍は5つの経路すべてで試練専用の台帳を使って検算した。

初心者役の通しプレイと、途中セーブを読み込んで誤入力や画面内の位置を測る技術QAは別に実施した。実際の小学生による観察とスマホ実機での確認は未実施。

## 公開修正版の結果

[配信したゲーム](https://github.com/maca-labs/kotsu2-quest/actions/runs/44988711088)で、初心者役は360×780の新規ブラウザーから、前章で書き出したセーブを使って完走した。受取額98と財布の合計998を同じ画面で確認した。徒歩で帰ったルカの家でも同じ受取明細を開けた。古龍の課題では「今回の確認へ」を押すと現在の操作に移り、確認番号・HPを維持したまま続きを操作できた。5問を終え、暁の冠の「装備中」を確認した。

公開版の技術QAは320×360と320×650で実施。誤った道から選び直したArbitrumは確定前に再読込みしても残った。申請後・着金後も再開し、それぞれの金額を確認した。両サイズで25画面を記録し、横方向のはみ出しとJavaScript例外は0件だった。ボスの受取99と冠の取得まで再確認した。自動テスト458件が合格した。
