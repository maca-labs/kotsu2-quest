# 国内の円から入金準備までの架空教材

従来のCR-01〜CR-04は、すでに練習財布へ1000 Mock USDCと0.001 Mock ETHが入っている状態から始まりました。今回のFI-01〜FI-03は、その手前の準備を一続きの架空シナリオとして追加します。実在する国内交換業者で使える購入・出庫手順の案内ではありません。

## 工程と資金の流れ

| クエスト | 工程数 | 操作と照合する結果 |
| --- | ---: | --- |
| FI-01 円を運び、教材コインを買う | 23 | 練習銀行200,000円から120,000円を入金。到着後にMCHI104枚を104,000円で購入。銀行80,000円、交換所16,000円＋MCHI104枚 |
| FI-02 自分の財布まで届ける | 21 | MCHI・みち道・自分のDEMO宛先を照合して104枚を出庫。教材費1枚を引き、財布への到着103枚を照合 |
| FI-03 資産と道を整えて旅へつなぐ | 26 | MCHI103枚→みち道USDC1,030→道替え費20→ArbitrumのUSDC1,010→ガス準備10 USDC→USDC1,000とETH0.001→既存の旅へ同じ資金の移管証跡 |
| 合計 | 70 | 固有IDを持つ、個別の画面移動・欄選択・入力・照合・確定・履歴確認 |

ミチコインMCHI、みち道MichiNet、こみち交換所、道案内交換所はすべて架空です。SORA、ほし道HoshiNetは今回の受取条件との不一致を直すための架空候補です。他のサービスでもその資産や道を使えない、という一般論にはしません。

Arbitrumは現実にもある名称を使っていますが、このゲームは実ネットワークへ接続しません。DEMO宛先は実際に送金できません。値段・交換比率・費用・最低数・処理時間はすべて教材用の架空値です。

「資産の種類を替える」と「同じ資産の道を替える」を別の確定にしています。道案内交換所は受取・交換・配送の処理費が見積書に含まれる架空サービスです。ガス未準備の実ウォレットで、実際の分散型交換をこの順番・費用で実行できるという説明ではありません。

## 二重配布を防ぐ引継ぎ

`funding-japan`台帳の最終確定前は、Arbitrumに1000 Mock USDCと0.001 Mock ETHがあります。最終確定でこの台帳の財布を0にし、`data.handoff`に移管先`journey`とその開始資金への参照を残します。既存の`journey`へ新しい資金を足しません。

そのため、新しい旅では準備からCR-01〜CR-03へ同じ資金の履歴としてつながります。古いセーブですでにCR-03等を進めていた場合は、FIを独立した準備の復習として扱います。既存の旅の残高・送金・出金を巻き戻したり、資金を追加したりしません。各運用ラボの独立した元手も変更しません。

共通エンジンでは新規の第5章をFI-01→FI-02→FI-03→CR-01の順にします。従来のCR工程を持つセーブを移行するとき、FIの未受講工程やXPを自動達成にしてはいけません。追加された台帳は開始状態として補い、旧履歴の再生・保存整合は共通エンジンの移行処理で扱います。

## 実装の接続点

- `js/content-funding.js`：3クエスト、70工程、日本語画面名・入力欄名・見積カード、初出用語、章印を与えない15の反応ポイント。
- `js/finance-funding.js`：`initialFundingScenarios()`、`applyFundingStep(state,step,value,context)`、`validateFundingScenarios(scenarios)`、`fundingScenarioSummary(scenario)`。
- 共通金融エンジンは新規台帳を開始状態へ結合し、FI操作だけを`applyFundingStep`へ渡します。既存の12の確定・受取イベントはすべて安定IDを持ち、再実行では変化しません。
- 画面はFIの`appTitle`、`screenTitle`、`panel`、`context`、`helpKeys`を使います。既存のHYPE現物や通販の画面を、FIの代わりに表示しないでください。
- `objectives`は`funding_basics`の5技能です。ガイド付きの証拠と、別条件の確認課題を分けます。

## 確認結果

2026-10-23、`node --test tests/funding.test.mjs`の7テストが成功しました。

- 3クエスト70工程のID・前提・日本語ラベル。
- 円入金・出庫・交換・道替え・ガス準備の処理中残高と、明示的な到着操作。
- 誤資産、誤ネットワーク、誤宛先、枚数超過、費用改変で確定を拒否し、正しい入力を保持。
- 5つの処理中チェックポイントをJSONで往復し、続きから最終引継ぎへ到達。
- 104枚購入、1枚出庫費、103枚×10、道替え費20、ガス準備10という数理と架空予算の保存。
- 全操作を2回ずつ実行しても資金・費用・到着・引継ぎが増えないこと。
- 新しい旅と、すでに進んだ旅の両方で、既存`journey`を加算・巻戻ししないこと。
- 残高、見積費用、移管参照の改変、重複した履歴、負数、非数を読み込み検証で拒否。

このファイル単独で確認したのは、教材データと金融状態の単体・結合動作です。ブラウザーの操作、狭い画面、共通セーブ移行、章移動、NPC演出への接続は、親プロジェクトの統合確認結果と区別してください。

## この追加でも扱わないこと

実在する国内サービスの現在の取扱銘柄、出庫可否、送金先制限、手数料、所要時間、交換・ブリッジ候補の比較を保証しません。現実の口座登録、秘密情報、銀行接続、実ウォレット、送金、売買も実装しません。ここで学ぶのは、必要な準備を分け、置き場所・資産・道・宛先・費用・到着を照合する考え方と、その架空の操作です。
