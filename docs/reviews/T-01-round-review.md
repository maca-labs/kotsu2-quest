# T-01 / quest_designer — 受注から帰還までの設計点検

対象の基準版: `c1cab3a48fb603ec0a1542131553a7883b1c9d83`。2026-10-23。
担当: `/root/quest_round_review`。製品変更は親から追加された `js/story-guide.js` と `tests/story-guide.test.mjs` のみ。

## 結論

受注→世界→洞窟→門番戦→操作→報告の部品はつながっている。初めての移動は短く、移動だけで金融の残高や学習XPは変わらない。一方、序章だけは最後の操作で町へ戻ると報告前に次町が案内される。これは修正した。方角が更新されないことと、逃走後のボタンが実際の行き先と違うことを親へ返した。

面白さの実証はしていない。ここではコードと状態の再現から、目的の矛盾や反復の原因を点検した。公開ブラウザーでの一周は親の別証跡であり、この担当の実施として数えない。

## 実施したこと

- AGENTS、PRODUCTION、CONTRACTS、WORKBOARD、DECISIONS、役割指示を読んだ。
- 製品仕様 `pointquest_codex_instructions.txt` §4〜9（町、移動、NPC、1操作、XP、ボス）と最新ユーザーの野外・洞窟・戦闘要求を照合した。旧仕様の「町でランダム戦闘をしない」と最新の「野外で進み具合に応じた敵」は両立している。
- `app.js`、`story-guide.js`、`rpg.js`、`rpg-world.js`、`rooms.js`、`rpg-ui.js` を点検した。
- Nodeから本物の `dispatch` を使い、PR受注→門番勝利→12工程を再現。基準版で67XP・手帳取得済み・未報告にもかかわらず次町案内になることを確認した。
- 同じ方法でPO完了後は依頼人への報告案内になることを確認した。PRとPOの差は学習stateではなく案内の分岐順だった。
- 修正後に `node --test tests/story-guide.test.mjs tests/rpg.test.mjs tests/rpg-world.test.mjs` を実行。32件成功、0件失敗、1.54秒。

未実施: 公開ブラウザー操作、実機スマホ、実際の初心者・小6程度の読み手、人間が感じる移動負担や面白さ。AIが初心者を演じた結果はない。

## 指摘と修正条件

### T-01-01 / Major / 序章の報告が案内から消える — 修正済み

根拠: PRODUCTION §1「頼まれた用事を終えるとNPCが反応」、最新ユーザー「案件→帰還まで一周」。

再現: 新規保存でPR-01を受注→門番を倒す→12工程を完了→町へ帰る→郵便屋にまだ話さずミッションを見る。

期待: 結果を郵便屋ミナへ知らせ、その後で第1章へ案内する。手帳や67XPの受取時点は変えない。

実際: `getStoryGuide` のCH-0完了早期分岐が未報告分岐より先にあり、第1章への出発を示した。他章は報告が先。

影響: 初めての人が「帰って本人に成果を伝える」を経験せず、別の町へ進む。仕様上の報告報酬を新設する必要はない。

修正: CH-0完了の案内を既存未報告判定の後へ移動。NPC journalをそのまま使い、報告フラグ、工程、XP、保存版は追加しなかった。

合格条件と結果: 未報告は郵便屋の家へ、再読込でも同じ。他NPCの会話では報告扱いにならない。ミナの会話後は第1章。既に取得した手帳、固定XP、金融scenarioが変わらない。すべて自動検証成功。公開画面は親が確認する。

### T-01-02 / Major / 方角の案内が歩いても変わらない — 親へ修正返却

再現: 世界へ出て目的の洞窟より東側や南側へ移動する。移動前後の `.expedition-wayfinder` を読む。

期待: 今の座標から見た方角が出る。

実際: `routeHint(map,pos,q)` は `renderExpedition` のときだけ評価。`walkExpedition` はcanvasと近くの入口だけを更新し、方角は出発時のまま。

影響: 方向の言葉を頼る初心者ほど、行きすぎた後の案内が逆になる。

最小修正案: 正常な移動の後に方角の文だけを再計算する。UIのための移動で工程やXPを増やさない。

合格条件: 洞窟の左右・上下を通りすぎると東/西・北/南が切り替わる。壁へ向かっても位置と案内が矛盾しない。

### T-01-03 / Major / 逃げた後の「道へ戻る」がスマホを開く — 親へ修正返却

再現: 門番を倒す→PO-01の13工程目などの進捗戦に入る→逃げる→「道へ戻る」を選ぶ。

期待: 道に戻る。作業へ直接戻れる場合は別の明確な選択肢にする。

実際: 勝利時と逃走時が同じ `onContinue`。未完了かつ門番撃破済みなら `openQuestPhone` へ進む。戦闘ログの「洞窟の入口へ戻った」も、座標を実際には戻していない。

影響: 逃走の結果と移動先が読み手の予想に一致しない。

最小修正案: 逃走後は地図に戻し、必要なら「保存した練習を続ける」も別に示す。ログは実際の移動に合わせる。入口の門番から逃げても戦いを省いて教材に入らない。

合格条件: 門番から逃走→地図、門番未討伐のまま。中間敵から逃走→地図または明示した練習ボタン。直後の1工程で同じ中間敵へ強制再突入しない。

### T-01-04 / Improvement / 任意の最終戦と帰還を言葉で区別する

再現: PR12工程、またはPO19工程を完了し、そのまま報告する。最終cpは未討伐で残る。

期待/実際: 教材と報酬は完了しているので後付け戦闘を義務にしなくてよい。一方で「結果を守る最後の魔物」は、倒してから成果を得る必須戦のように読める。

最小案: 「腕だめし」「寄り道の魔物」など任意性を示す。報告主導線に最終戦を強制追加しない。帰還直行は「村へ帰って報告」等、選ぶと町/家へ移動することが分かる文にする。

合格条件: 教材の最終確認、任意の旅戦、章ボスが別だと読み分けられる。必要な工程/章の確認を削らず、コインや報酬を追加発行しない。

### T-01-05 / Improvement / 壁へ押した回数が野外遭遇の間隔に混ざる

`walkExpedition` は `result.moved` と無関係に `fieldSteps` を増やす。遭遇開始だけは移動時なので、壁を11回押した後の1歩で遭遇することがある。HPや報酬の不整合ではないが、「12歩」の意図には合わない。

最小案: 成功した移動だけを歩数へ加算する。退出・門への移動で早returnする場合の数え方もそろえる。

合格条件: 壁へ押し続けても遭遇カウンターが増えず、成功歩行だけで間隔が進む。逃走敵の再会は可能でも、1工程ごとの強制戦闘に戻らない。

## 戦闘の単調さとショートカット

初門番は攻撃7・敵HP14/防御1で、強打10→通常6の2行動で勝つ。予告された強攻撃は3ターン目なので、最初の戦いで防御が必要になるわけではない。これは最初の操作を覚える負担としては短いが、「予告を読む戦術が最初から楽しい」とは証明できない。後の敵、武具の購入、残HPの管理によって違いが出る設計である。初周のレビューだけを理由に敵HPや固定報酬を増やす提案はしない。

ショートカットは仕様§4にもあるアクセシビリティの入口。歩かない人にも同じ教材工程が必要で、門番前にはスマホへ入れない。世界の行き先一覧はdetails内、初回の主導線は南門→歩くになっている。町/家への直行を許すこと自体は問題にしない。主導線まで毎回ワープして探索を無くすことと、帰り道の繰り返しを省く選択肢は分ける。

親の公開一周では、出発前・洞窟到着・門番後・途中保存・報告後に「次の目的が一つ分かるか」を観察してほしい。移動を止めてページをスクロールする回数、意図しない遷移、同じ敵への直後再突入は、好みと別に数えられる。
