### AB02-F05 — 逃げた前案件の進捗敵が、次案件の洞窟歩行で再出現し案件選択まで戻す

- 優先度: Major。逃走後の再出現と、進行中案件の意図しない切替を再現。
- 対象: 基準guide13の `app.js walkExpedition / automaticEncounter / continueAfterBattle`、`rpg.js getAvailableEncounters / RPG_BATTLE_START`。親の他修正で行番号が動くため関数名を基準とする。
- 仕様根拠: CONTRACTS R「逃げた記録は自動再提示から除外し、地図の再会は可能」「新規未着手案件は門番→説明→操作」。必要な旅戦を残し、ユーザーの意思と異なる旧案件の再開を挟まない。
- 原因: `automaticEncounter` は逃走したbattleのencounterIdをeventLogから除外しactiveQuestKeyも限定する。しかし歩行の12歩判定は `available && !defeated && checkpoint>0 && 同章` だけで選ぶ。逃走済・別案件・完了済を除外していない。`fieldSteps` は世界と洞窟で共有し、エリア移動時にリセットされない。`RPG_BATTLE_START` は遭遇のrecordKeyをactiveQuestKeyへ選び直すため、旧案件の遭遇は表示だけでなく実際の選択案件を変える。
- 再現手順（メモリ上の正規engine）:
  1. CH3の条件メモ/FX01受注、cp0門番勝利、FX01の12工程を実dispatchで作る。
  2. `enc:FX-01:cp:12` を開始し、実 `RPG_BATTLE_ACTION flee` で逃げる。
  3. FX01の残り6工程、NPC報告、FX02受注をdispatchする。街道の小枝の竜を開始して逃げ、海洞へ移動する。
  4. UI歩行カウンターを23（次が12の倍数）とする。実 `getRpgSpawn('cave:CH-3','world')` と実 `stepRpgMap` を用い、sourceから取り出した `walkExpedition(0,-1)` を実行する。DOMはquerySelectorなし、描画のみ省略した。
- 実測出力:

```json
{"before":{"active":"FX-02","steps":23,"available":["enc:FX-01:cp:12","enc:FX-02:cp:0"],"automatic":null,"location":{"mapId":"cave:CH-3","x":12,"y":16}}}
{"afterOneUp":{"active":"FX-01","steps":24,"encounters":[{"id":"enc:FX-01:cp:12","questId":"FX-01"}],"position":{"mapId":"cave:CH-3","x":12,"y":15}}}
```

- 期待: FX02の門番へ向かう段階で、逃走済み/報告済みのFX01進捗敵を自動出現させない。旧敵と再会したい場合は、その旧案件へ意図的に訪ねる操作を残せる。
- 実際: 同じ状態で `automaticEncounter()` はnullなのに、歩行判定は旧イノシシを開始し、FX02からFX01へactiveQuestKeyを戻す。観察の「洞窟上1歩でイノシシ」に一致する具体的経路がある。
- 影響: 新しい用事の門番より古い敵が先に出て、何の用事を進めているか見失いやすい。次の帰還/再開の案内も旧案件基準になり得る。学習データの消失や追加XPは本再現では認めなかった。
- 最小修正案: 洞窟の自動歩行遭遇も `automaticEncounter` と同じ対象選別を使い、少なくともactive record一致/逃走除外をそろえる。門番未勝利の新規案件の途中へ別案件の進捗敵を挟まない。event/ID/固定報酬/手動の再戦入口は変更しない。単に全遭遇を無効化して解決しない。
- 合格条件:
  - 上記状態+fieldSteps23で上1歩してもbattle開始0、activeQuestKey=FX02、進捗/金融/XP保持。
  - 同一案件のcp12から逃げた後、13工程へ戻る操作や歩行でもそのcp12を自動再提示しない。
  - 未逃走の現在案件がcp9/12へ達した際は、必要な進捗敵が一度現れる。未着手FX02の門番は引き続き必要。
  - 手動で旧敵へ会い直す入口を維持し、再戦初勝利のコインを重複付与しない。

### 中断頻度について、バグと改善を分けた評価

- 「毎工程の再登場」は確認できない。`runStep` は同一敵の勝利済・逃走済を除き、既存checkpointでだけ次候補を出す。FX01はcp0/12/18、FX02はcp0/9/20。最終工程ではnextがなく、自動進捗戦は開始しない。
- 通常街道は初回4成功歩、以後同じ章で20成功歩。開始時にroadSteps=0へ戻し、逃走もattemptsへ残るため、同じ通常街道敵が逃走直後の次1歩で再度出る構造ではない。砂漠は別の明示された強敵で、逃走後8歩の猶予を置く。壁押しは成功歩へ数えない。

- 逃走後の「道へ戻る」は表示どおりで、記録を保持する。進捗戦を避けてスマホへ戻るのにさらに案内展開とナレーション開始を要する点は、観察上の補助操作負担として記録する。5操作あったことだけで進行不能とは扱わない。
- 小さい改善案: 進捗戦から逃げ、元の案件が未完了かつ入口門番は勝利済みなら、結果画面に既存の「道へ戻る」を残したうえで「いまのスマホ練習へ」を任意の復帰として出す。新規受注、入口門番逃走、通常街道、完了済案件へはこの近道を出さない。既存の説明は読めるまま、再開自体にSTEP/XPを足さない。
