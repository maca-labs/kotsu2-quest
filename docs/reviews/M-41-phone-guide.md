# M-41 — コピー元から入力先までを一つの道案内にする

担当: phone_engineer / 2026-10-23。対象は PR-01、PO-01、DX-01。ユーザーの「コピー・指示・スマホが別々で分かりづらい」という指摘に対し、ゲーム内スマホの現在操作のそばへ表示する短い案内を実装した。親が app.js / phone-panels.js の接続を所有する。本担当の製品編集は新 `js/phone-guide.js` と専用 `styles/phone-extension.css` の追加部分のみ。

## 表示の契約

`getPhoneGuideView(state,quest,step)` は純粋な読取。`renderPhoneGuide({document,state,quest,step})` は DOM element または null を返す。対応外の依頼は null。

- 短い3地点: メールでコピー → 入力中のメモ/モール/取引所へ戻る → 合言葉/確認コード欄へ貼る。
- 現在の工程と完了記録から、準備、コピー元、戻る、入力先、保存/認証、完了を分ける。コピーしたことを、貼り付け/保存/認証済みとは扱わない。
- コピー済みの値を表示するには、対応メールの read、対応するコピー工程の completedSteps、現在の内部 clipboard と対応 mail.code の一致が**すべて必要**。コピー工程は PR-01-006 / P014 / DX-01-S013。
- 上の条件が満たされない場合、`copyText:null` とする。未読メールの code、本編前の用事の合言葉、別サービスの数字を view や DOM に混ぜない。「この用事のコードはまだコピーしていません」または「いまはゲーム内コピーにありません」と区別する。
- 3地点の詳しい名前とコピー/貼り付けの意味は details へ収める。DX のメール認証後はプロフィール入力の邪魔にならないよう、完了見出しと折り畳みに縮める。
- UI は工程、メール読了、資金、XP、報酬、保存へ書き込まず、OS の clipboard API も使わない。案内そのものに工程を進めるボタンはない。

親はこの `copyText` を既存メモの内部コピー表示にも使用し、前の用事の値を無条件で出す旧表示を直す。操作対象の強調・主操作・readonly の貼り付け欄は親の編集範囲。

## 学習レビュー後の追修正

DX でコピー後に別の用事へ行き、別コードをコピーしてから DX 入力へ戻ると、専用パネルだけが raw clipboard 非空を「コピー済み」と扱う矛盾が指摘された。親の追加割当で `js/phone-extension.js` の確認コード入力分岐を修正した。

- 本編は `getPhoneGuideView(...).copyText` の3条件をそのまま使い、案内・専用パネル・貼付けで送る値を一致させる。
- 無効な場合は値や貼付けを出さず、「今回の確認メールへ戻り、コピーし直そう」と、既存メール画面へ戻るボタンを示す。本編メール再訪時の内部コピー機構を使用し、既達成 STEP を再実行しない。
- 独立復習は snapshot の mailOpened が true で、snapshot.clipboard がその復習 profile の verificationCode と一致する場合だけ貼り付けられる。本編メール読了や clipboard へ fallback しない。
- 復習メールの再訪とコピー回復は親の app.js 所有範囲。専用パネルは onAppNavigate('mail') を通知するだけで、snapshot や XP を直接変更しない。

追加2件のテストで、他のコードが入った本編、無効な復習コード/未読/未設定、正しい復習コード、メールへ戻る通知、実際に onAction へ送る値、本編/復習 state 不変を確認した。親の UI 接続と実ブラウザー確認は本担当の合格範囲に含めない。
