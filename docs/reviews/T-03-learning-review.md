## Major: T-03-01 地図までの反復スクロール

- 根拠: ユーザーの最新指示。AGENTS の「目的が画面に示される」「狭い画面」「一つの操作に結果」。
- 再現: 町へ入る / 洞窟から町へ戻る / 設定から町へ戻る。町の先頭を表示する。
- 実際: app 81–86 で見出し→長いミッション→HPと宿→相談→町の変化→地図の順。`travelArea` は先頭へ戻し、`leaveRoom` は地図へ直接スクロールするため、遷移ごとに視点も変わる。室内・野外にも地図前の説明カードがある。
- 期待: 最上部に「現在地」「次の一歩」「メニュー」。続いて地図と操作。物語全文・三段階の進捗・一覧・店・装備・記録等はメニューから開く。
- 影響: 移動したい操作ごとに探し直す。説明文が多いほど、十字キーが最初の画面から押し出される。
- 修正案: 例「現在地：旅立ちの村」「次：郵便屋の家で、ミナに話そう」「メニュー」。詳細を隠しても用語相談、保存、自由な章選択へ到達できるようにする。メニューに入らないと次の目的が分からない構成にはしない。
- 合格条件: 320×720 / 390×844 で町・室内・野外・洞窟の入場直後に現在地/次目的/メニューボタンが分かり、地図と十字キーを操作するためのページスクロールが不要。メニュー開閉で進捗とHPは変わらず、閉じたら同じ場面へ戻る。

## Major: T-03-03 逃走後「道へ戻る」が端末へ移る

- 根拠: 1操作1指示、押したときの結果と名称の一致、戻れること。
- 再現: 門番勝利済みの案件を洞窟内で進め、区切りの敵から逃げる。結果の主ボタン「道へ戻る」を押す。
- 実際: rpg-ui 67 は「道へ戻る」。app 211 の共通 onContinue は、未完の案件かつ入口戦不要なら `openQuestPhone` へ進む。rpg 55 のログも「洞窟の入口へ戻った」と書くが、逃走コマンド自体はlocationや歩行座標を変えない。
- 期待: 実際に端末へ戻るなら「戦いをやめて練習をつづける」、地図へ戻すなら「道へ戻る」。入口へ移さないなら入口へ戻ったとは書かない。
- 影響: どの画面へ戻るか予測しづらく、逃げると進捗が残るという安心説明も弱くなる。
- 合格条件: 入口戦からの逃走、途中戦からの逃走の両方で、主ボタンの名前と遷移先が一致。逃走で記録/コインを失わず、同じ敵の自動再提示ループにならず、地図で再挑戦できる。

## Improvement / 低工数で推奨

### T-03-04 初戦の言葉と再挑戦

HP、ダメージ、ターンは初出時に前提説明がない。行動ボタンには短い説明があり、敵の予告も具体的なのは良い。「HPは体力。0になると町へ戻る。記録やコインは残り、宿で無料回復できる」を初戦の短い説明か「戦い方」で聞けるようにする。敗北を経験するまで保存が守られるか分からない状態を減らす。敵の「力をためる→強い攻撃」という予告は維持する。

### T-03-05 移動・戦闘の反復と目的

コード上、各案件の入口は同じ tier 0（敵HP14/防御1）。実 dispatch の新規PR門番は、初期杖込み「強打10→攻撃6」の2操作で倒れ、HP29・12コインとなった。初戦が短いのは妥当。ただし全案件の入口と途中戦を同じ仕方で処理する反復が、教材の前後に足された定型作業になる可能性がある。これは人間の退屈の実測ではなく仮説。

まず「勝利12枚→次の品まであと何枚」のように装備へつながる理由、洞窟で何を取り戻したか、帰還後の村人の反応を短く見せる。帰還の近道と、途中敵から逃げて練習を続ける選択を保つ。歩数の増加や固定XPの変更を対策にしない。
