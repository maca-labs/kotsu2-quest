## 指摘・実測依頼

### MQA-01 — 教材パネル全文が実操作より前に入り、指示と入力が離れる

- 位置: `js/app.js:103–108`、`js/phone-extension.js:72–97`、`styles.css` の760px以下 `.phone-body`。
- 仕様根拠: 1操作1指示、小6程度でも現在の目的と押す場所が分かること。
- 再現: スマホ幅でDX-04またはDX-05の数量・指値入力まで進める。「いま、すること」を読み、実際の入力欄を探す。
- 期待: 今の指示から入力欄へ短い移動で到達でき、必要な板・見積・資金は引き続き確認できる。
- コードから確認した実際: 指示→教材パネル全体→通常入力の順。板2表、見積、現在残高、注文や約定履歴が入力前に描かれる。モバイルではphone-bodyのmax-height制限がない。履歴は後半ほど増える。
- 親の公開ブラウザー実測: 390×844 CSS px、DX-01 S005の欄を押して次工程へ進むと、次の入力欄はy=834 / 高さ46pxで、画面下端の10pxのみ見えた。今の指示は上へ隠れた。親からの観測報告として記録し、担当自身の操作とは扱わない。
- 影響: 1操作後に、次の指示と入力が見える位置へ移らない。見切れた入力を探してスクロールする必要がある。板売買後半の距離は別途実測が必要。
- 優先度: Major。序盤で問題が実測されたため修正対象。
- 修正後条件: DXの初期・履歴付き後半、LD、LVの代表入力で、現在の指示と操作を近く表示する。必要な情報を消さず、工程と金額の確認は維持する。

### MQA-02 — 進行中の場面が狭い画面で常時上部を占有する

- 位置: `styles.css` 末尾760px以下 `.quest-play-layout .adventure-scene`、`styles/world-extension.css` の `.course-plan` / `.course-note`、`js/ui-adventure.js:28–38`。
- 再現: 320〜430pxでDXとLVの操作中に下へスクロールする。短い縦幅でも入力欄・決定ボタンを操作する。
- 期待: 村人や敵の反応が分かり、入力・ボタンのための空間も確保できる。
- コードから確認した実際: 場面全体がsticky / top:0 / z-index:5。敵名、吹き出し、目標、寄り道説明、選択状況、相談3ボタンをまとめて固定する。画面高に応じた制限や縮小状態はない。
- 親の公開ブラウザー実測: 390×844 CSS px、DX-01 S005からの操作中、stickyの場面はy=0 / 高さ224pxだった。観測された固定占有の高さは画面高の約27%。MQA-01の見切れと同時に発生。
- 影響: 短い画面で操作へ使える空間を減らす。ソフトキーボードとの実際の重なりは未確認。デスクトップ縮幅は実機キーボードの代用にならない。
- 優先度: Major。実測の操作見切れを踏まえ、固定部の占有も修正対象。
- 修正後条件: 代表の短い縦幅で固定部と操作が競合しない。最新反応を読み直せる手段は残す。実機キーボードが使えなければ未確認とする。

### MQA-03 — 序章の最後に押す「町へ戻る」が指示より上にある

- 位置: `js/app.js:108`、`js/app.js:113–115`。
- 再現: PR-01の最後まで進める。「スマホの外にある『町へ戻る』」を読み、該当ボタンを探す。
- 期待: 外側の戻る操作で最後の1工程と手帳を確定することを保ちつつ、押す場所が迷わず分かる。
- コードから確認した実際: 説明はphone-body内、該当ボタンはphoneより前にあるsceneの末尾。モバイルではsceneの子が縦並びになるため、本文を読み終えた位置から逆スクロールが必要になる。
- 影響: 最初の達成が確定する重要操作を、ゲーム内スマホ下部の「戻る」と取り違えやすい。実測未実施。
- 優先度: Major候補（序章の導線）。
- 修正後条件: PR-01最終工程から、画面幅320/390pxで正しい外側ボタンを特定して1回押せる。手帳やXPを早めに付与せず、連打でも重複しない。

### MQA-04 — 酒場・長老・ことば説明でダイアログの名前参照が消える

- 位置: `index.html:5` の `aria-labelledby="modal-title"`、`js/ui-adventure.js:16`。
- 再現: 酒場または「これは何？」を開く。ダイアログのaria-labelledby参照先を確認する。
- 期待: 開いている会話・説明の題名がダイアログ名になる。
- コードから確認した実際: openHelpのshow関数はmodalを置換してIDなしh2を作るため、`modal-title`が存在しなくなる。通常showDialogはIDありh2であり、この経路に固有。
- 影響: スクリーンリーダーを使うスマホ利用者に、開いた相談画面の名前が渡らない。コード上の参照欠落は確定、実際の支援技術での読み上げは未確認。
- 優先度: Improvement（確定した修正対象）。
- 修正後条件: すべてのopenHelpメニューでaria-labelledbyのIDが存在し、そのテキストが現在の題名と一致する。

### MQA-05 — 開いたダイアログの差し替え時、先頭への復帰がない

- 位置: `js/app.js:34` showDialog。対照として `js/ui-adventure.js:16` showはscrollTop=0がある。
- 再現: 小さい縦画面で長い依頼・条件説明を下までスクロールし、閉じずに次の依頼説明へ切り替える。例: FX案件条件→「条件を手帳に控える」→受注説明。
- 期待: 新しい説明は先頭の目的から読める。
- コードから確認した実際: modal.replaceChildren後、既にopenならshowModalを呼ばず、scrollTopも変更しない。ブラウザーがどこに保持するかは実測が必要。
- 影響: 新しい説明の前半を見ず、受注ボタンだけに到達する可能性。
- 優先度: Improvement候補。実測で再現すれば修正。
- 修正後条件: 長い説明の下端から次の説明へ切り替えたとき、題名と目的を表示して始める。

## 静的に確認できた良い土台

- viewportメタあり。Vanilla JavaScriptと相対URLの構成を維持している。
- ボタンは原則min-height:44px、input/selectは46px以上。電話内の主要な文字と入力は16px以上で、iOSの小さい入力文字によるズームを避ける土台がある。
- 760px以下で町・ボス・スマホのレイアウトを1列へ切り替える。
- 板2表はtable-layout:fixedとoverflow-wrap:anywhere、台帳はminmax(0,...)で狭い幅への配慮がある。
- 酒場の絵で選びにくい人にも、同じ相手を名前のボタンから選ぶ入口がある。
- 相談を閉じても学習・資金・工程を変更しない設計を保つ。
