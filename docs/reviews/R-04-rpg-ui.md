## 実装した契約

`renderRpgBattle({document,state,onAction,onContinue,onTown})`、`renderRpgShop({document,state,onBuy,onEquip,onLeave})`、`renderRpgEquipment({document,state,onEquip})` は DOM Element を返す。表示に `getRpgView(state)` の実値を使い、UIが HP / コイン / 資金 / XP / 工程を書き換えない。

戦闘では敵と旅人のHP、敵の次の予告、装備込みの攻守、直前の行動と全記録を表示。engine の actions に従い、こうげき/まもる/強打1回/にげるを出し、使用済みの強打を無効化する。onAction へ action ID / battle ID / 現turn をまとめて送るため、engine が古い画面の操作を識別できる。

勝利は初勝利のコインと再戦を分け、逃走/敗北で勝利コインを得たことにしない。勝利後「用事の続きを進める」、逃走後「道へ戻る」、町の宿への復帰を callback として返す。宿への移動と無料回復は親の既存コマンド接続が担当する。

店では価格と攻守の効果、所持冒険コインを表示し、「この品を買う」→同じカード内の価格/所持数確認→「この内容で買う」で初めて onBuy(id) を送る。取消もできる。所持金不足を無効化し、購入済みと装備中を分ける。購入後の onEquip は購入操作とは別。

装備画面では購入した武具と旧章の所持装備を両方描く。装備中の判定・合計の強さは実 view.stats / itemIds を使用する。購入しただけで装備済みに見せず、身につけてから上の合計が変わる。武器は旧所持の杖へも戻せる。防具を null へ外す API は現在ないため、UIで状態を直接書き換える操作は追加していない。この点は親へ伝えた。

冒険コインと金融教材の円/ポイント/暗号資産の区別、大事なスマホ確認を装備で飛ばさない短文を表示。文字は通常の読みやすい字体、主ボタンは48px以上、画面600px以下では商品を1列、戦闘のHPを縦へ並べる。入力・選択・結果はボタンごとの明示操作で進む。アニメーションは追加せず reduced-motion に従う。

人物、六種の敵、武具、店内はこの module の canvas へ独自の矩形で描いたローカルのドット絵。外部素材/サービスへ接続しない。画像の意味は aria-label と画面の文字で読める。

## 確認

`node --test tests/rpg-ui.test.mjs`: **5 PASS / 0 FAIL**。

- 実 engine の初戦を使い、HP/予告/実攻守と action/battle/turn の通知を確認。描画とcallbackの通知だけでは state を変えない。
- 使用済み強打は callback を発火せず、まもる/にげるには現turnを渡す。
- 実勝利/再戦/逃走/敗北の表示と続き/宿 callback、初勝利だけのコイン表現を確認。
- 実2勝で得た27枚を使い、購入前の確認と取消、24枚の購入、購入済みからの装備、装備済みの無効化を確認。
- 実所持金不足で購入できず、買った時点は攻撃7、身につけた後はengine由来の攻撃10になることを確認。

`node --check js/rpg-ui.js` 成功。テストのDOMは最小の要素代替を使い、canvas context は null にして文字/操作契約を確認している。ドット絵の実画素、320/390pxの実描画、ブラウザーでの操作、公開URL、実機、人間の理解/面白さは本担当では未確認で、親の統合確認へ引き継いだ。孫エージェントなし。
