# 第6章・鏡の塔の無期限先物と帰還

## 最初の公開版で迷った場所

小6でスマホ操作が苦手な人を想定したAIが、Windows版Chromeの360×780でプレイした。初回は以前の公開プレイの操作記録を通常のゲーム処理で再生し、第5章最後の予約を先物にしたセーブから始めた。同時に新規ブラウザーで第5章を最初から遊び、先物を自分で選んだ未編集のセーブもゲームから書き出した。「買い・ロング」は選べたものの、下がったらどちらが損をするのか、その場の案内から説明できなかった。証拠金の入力後に出る式から100・200・900の違いは読み取れた。

別担当が320×360と320×650で確認した。高さ360pxでは注文のボタンと取引額200・手元900を一緒に読めず、ショートや5倍を選んだときの訂正文も画面外に出た。証拠金の欄では正しい全角の数字が拒否された。決済後に上の明細まで戻ると、閉じた建玉の価格が一律に100と表示され、本編の決済価格95やSLの成立価格96.5と食い違っていた。

## どのお金が動いたか

以下はこのゲームだけの教材値。金額の単位はMock USDC。

| 場面 | 取引に使うお金・取引額 | 使えるお金 |
| --- | --- | --- |
| ソラの注文を準備 | 証拠金100を2倍にすると取引額は200。開始価格100で数量2 | 確定前は1,000 |
| ロングで注文を確定 | 取引に100を分ける。値動きは200ぶん | 使わずに残した900 |
| 教材価格100から95へ | ロング数量2は評価損10。取引中の100の今の値打ちは90 | 手元の900は動かない |
| 数量2をすべて決済 | 損10が確定し、90が戻る。取引中の数量は0 | 900＋90＝990 |
| ルカと出金 | 990を送ると、教材費1を引いた989が処理中になる | 受取前の財布0。到着後の財布989、ハイリキ0 |

損が広がったときに自動で決済を始める注文（SL）の小練習では97が合図、実際に成立した価格は96.5。損7で93が戻り、その小練習の手元は993になる。資金調達料の例はロングが0.02を1回払う。清算の例は価格52で取引中の資金4が維持に必要な5.2を下回るので、4が戻り、手元は904。どの例でも本編の990はそのまま。

章ボスは専用の証拠金50で取引を終え、費用1を引いた49を別の財布で受け取る。第5章の旅で入金した99、旅の財布900・ガス用0.0009 ETHとも分けて確かめた。

## 計算とセーブの検証

金融担当が本編48工程、出金26工程、章ボス5課題31操作、条件を変えた確認5課題33操作を検算した。15回の保存復帰、104件の済んだ操作の再送、35件の誤入力を確認。方向・倍率を自由に選ぶ別の依頼でも、ロングとショート、1・2・5倍、価格95・105を組み合わせた12通りを照合した。向きによって損益の符号が逆になり、どの組み合わせでも獲得経験値は同じだった。

## 修正後の小さい画面

修正版を配信したGitHub Pagesで、Windows版Chromeのタッチ画面を320×360と320×650に設定した。それぞれ固定ラボ48工程と出金26工程を、各依頼の通常の開始セーブから操作した。214画面で、次の操作対象の見切れ、通知との重なり、横へのはみ出し、無効な数値の表示、ブラウザーの実行エラーはいずれも0件だった。自動テスト473件もすべて合格した。[公開版の配信記録](https://github.com/maca-labs/kotsu2-quest/actions/runs/45010118917)

ロングとショートを切り替えると、1枚の価格が100から101に上がった場合と、99に下がった場合の得・損がその場で変わった。倍率1・2・5を選び直しても、確定前の手元1,000はそのまま。5倍を選んで再読込したときも、証拠金100・取引額500・数量5の試算と選択欄が同時に見えた。全角の入力、間違いの訂正、下書きを開き直してからの確定も確認した。[ショートを選んだ画面](./perp-verification/short.png) ／ [5倍の試算を再開した画面](./perp-verification/leverage-resume.png)

本編で取引額200と証拠金100を分け、決済の直前には今使える900、戻る予定90、決済後の予定990を確認できた。清算の見学から本編へ戻るボタンには、見学側の904と、これから戻る本編の990が並ぶ。[注文する直前](./perp-verification/order.png) ／ [決済する直前](./perp-verification/settle.png) ／ [別口座から本編に戻る画面](./perp-verification/back-from-liquidation.png)

高さ360pxでは、完了明細の下半分へスクロールするまで報告する金額が見えなかった。最終版では、ソラへ帰るボタンのすぐ上に決済時の990、ルカへ帰るボタンのすぐ上に財布へ届いた989を表示する。両サイズでそれぞれの徒歩ボタンを押し、洞窟の出口案内まで戻れた。完了を確認した14画面でブラウザー例外は0件。[ソラに報告する前](./perp-verification/return-to-sora.png) ／ [ルカに報告する前](./perp-verification/return-to-luka.png) ／ [最終版の配信記録](https://github.com/maca-labs/kotsu2-quest/actions/runs/45010388142)

## 第5章で予約し、天空城へ帰るまで

初心者役は新しいChromeの360×780で、第5章を遊んで書き出した未編集のセーブを通常の設定画面から読み込んだ。第6章の依頼はまだ0件。ソラから依頼を受け、南門から帰り帆の洞窟へ歩き、敵と戦って練習スマホを開いた。[第5章の予約](./perp-verification/chapter-five.png) ／ [帰り帆の洞窟での戦闘](./perp-verification/cave.png)

ショートの試算で「数量1なら価格100→101で損1、100→99で得1」と説明できた。1・5・2倍を見比べ、5倍にしても手元は1,000、まだ注文していないことを確認した。本編のロング・2倍で価格100から95へ進め、確定前の「戻る予定90、決済後990」が、確定後に「建玉0件、手元990」に変わるまでを確認した。48工程を終え、自分で洞窟を出てソラに報告した。[ソラと見た決済明細](./perp-verification/sora.png)

同じ旅のままルカの依頼を受け、再び洞窟へ向かった。出金26工程で、送った990と、費用1を引いて財布へ届いた989を照合した。洞窟からもう一度歩いて帰り、学者の家でルカに受取明細を渡した。通常の書き出しデータでも両方の徒歩帰還・NPCへの報告、損失10、ハイリキ0、財布989と他ラボ未受講を確認した。[ルカと見た受取明細](./perp-verification/luka.png)

最終の公開コードでも自動テスト473件すべてが合格した。初心者役はAIが担当した。人間の小学生による理解度・楽しさ、スマホ実機のソフトキーボードとiOS Safariでの操作は未確認。
