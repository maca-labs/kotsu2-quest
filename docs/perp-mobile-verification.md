# 第6章・鏡の塔の無期限先物と帰還

## 最初の公開版で迷った場所

小6でスマホ操作が苦手な人を想定したAIが、Windows版Chromeの360×780でプレイした。初回は以前の公開プレイの操作記録を通常のゲーム処理で再生し、第5章最後の予約を先物にしたセーブから始めた。同時に新規ブラウザーで第5章を最初から遊び、先物を自分で選んだ未編集のセーブもゲームから書き出した。「買い・ロング」は選べたものの、下がったらどちらが損をするのか、その場の案内から説明できなかった。証拠金の入力後に出る式から100・200・900の違いは読み取れた。

別担当が320×360と320×650で確認した。高さ360pxでは注文のボタンと取引額200・手元900を一緒に読めず、ショートや5倍を選んだときの訂正文も画面外に出た。証拠金の欄では正しい全角の数字が拒否された。決済後に上の明細まで戻ると、閉じた建玉の価格が一律に100と表示され、本編の決済価格95やSLの成立価格96.5と食い違っていた。

## どのお金が動いたか

以下はこのゲームだけの教材値。金額の単位はMock USDC。

| 場面 | 取引に使うお金・取引額 | 使えるお金 |
| --- | --- | --- |
| ソラの注文を準備 | 証拠金100を2倍にすると取引額は200。開始価格100で数量2 | 確定前は1,000 |
| ロングで注文を確定 | 取引に100を分ける。値動きは200ぶん | 使わずに残した900 |
| 教材価格100から95へ | ロング数量2は評価損10。取引中の100の今の値打ちは90 | 手元の900は動かない |
| 数量2をすべて決済 | 損10が確定し、90が戻る。取引中の数量は0 | 900＋90＝990 |
| ルカと出金 | 990を送ると、教材費1を引いた989が処理中になる | 受取前の財布0。到着後の財布989、ハイリキ0 |

損が広がったときに自動で決済を始める注文（SL）の小練習では97が合図、実際に成立した価格は96.5。損7で93が戻り、その小練習の手元は993になる。資金調達料の例はロングが0.02を1回払う。清算の例は価格52で取引中の資金4が維持に必要な5.2を下回るので、4が戻り、手元は904。どの例でも本編の990はそのまま。

章ボスは専用の証拠金50で取引を終え、費用1を引いた49を別の財布で受け取る。第5章の旅で入金した99、旅の財布900・ガス用0.0009 ETHとも分けて確かめた。

## 計算とセーブの検証

金融担当が本編48工程、出金26工程、章ボス5課題31操作、条件を変えた確認5課題33操作を検算した。15回の保存復帰、104件の済んだ操作の再送、35件の誤入力を確認。方向・倍率を自由に選ぶ別の依頼でも、ロングとショート、1・2・5倍、価格95・105を組み合わせた12通りを照合した。向きによって損益の符号が逆になり、どの組み合わせでも獲得経験値は同じだった。
