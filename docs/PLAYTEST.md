# プレイ観察の計画

状態: 観察手順を整備済み（KQ-050、2026-10-23）。人間観察は未実施。参加者0人、観察データ・達成率はまだ存在しない。
目的: 初心者が「次に何をすればよいか」「なぜ行うか」を理解し、続きに興味を持つかを調べる。

## いつ、誰と試すか

最初の一周と第1章が触れる段階で、金融やゲームに詳しくない成人の協力者に試してもらう。
文章は小6程度の理解を想定するが、実際の小学生に金融取引を勧める課題にはしない。
最初は3〜5人程度の小さな観察から課題を見つける。この人数は設計上の目安で、
学習効果や継続率を統計的に保証するものではない。
参加者がいなければ観察用手順を整えて実装を進め、実測欄は未実施のままにする。

## 1回の手順

1. 対象の版・端末・画面幅・事前経験を記録する。個人を特定しない参加者番号でよい。
2. 「町の人の依頼を一つ終えてみてください」と目的だけ伝える。
3. ヒントはゲーム内のものを使える。観察者が手を出した場合は、時刻と助けた内容を記録する。
4. 目的が分からなくなった箇所、意図した操作、実際に押した場所、画面の反応を記録する。
5. 途中で閉じて再開し、続きから何をすればよいかを確かめる。
6. 同じ技能を条件の違う短い課題で試す。正しい操作と、その理由を別々に記録する。
7. 最後に、面倒だった箇所、気持ちよかった箇所、次の依頼をやりたいか、その理由を聞く。

ゲーム内の候補値と架空データを使う。本人の口座・秘密情報は観察材料にしない。
録画や外部へのデータ送信を初期必須にしない。ローカルなメモで始められる。

## 記録するもの

| 観点 | 観測 | 解釈上の注意 |
| --- | --- | --- |
| 最初の目的 | 何をするゲームか説明できたか、分かるまでの時間 | 時間だけで理解を決めない |
| 最初の達成 | 序章の完了と報酬までの実時間、助けの回数 | 初回5分は目標仮説。未測定を達成済みにしない |
| 操作の迷い | 戻る、探す、別アプリ、入力消失、止まった場所 | 戻る行為は確認のためなら正常 |
| 必要な判断 | 宛先・送料・lot・受取等を確認したか | 速さや利益で学習を採点しない |
| 条件の違う課題 | 正しく操作できたか、理由を言えたか、ヒントを使ったか | ヒント利用でゲーム報酬は減らさない |
| 達成感 | 何を達成したと思ったか、装備や町の変化に気づいたか | AIの感想で埋めない |
| 続きへの興味 | もう1件選んだか、その理由 | 意向を長期継続率と呼ばない |

無操作が長いだけで「退屈」と判定しない。読んでいる、考えている、生活上の中断もある。
時間を観測するなら、参加者の中断、観察者の説明、画面切替を区別する。
熟練度のゲーム内点数と、観察上の理解度を同じ数字だと扱わない。

## playtest_analystの出力

- 観測した事実: 画面、行動、発言。対象の版と参加者数。
- 推測する原因: ほかにあり得る説明も添える。
- 修正案: 一つの原因に対応する小さな変更。
- 変えないもの: 工程ID・金額・固定XP等、今回の修正の範囲外。
- 次回の確認: 同じ課題または条件違いの課題で何を見るか。
- 未実施: データがなく言えないこと。

例:
事実: 参加者がメールの画面から登録フォームへ戻る場所を探した。
仮説: ホームとアプリ切替の違いが説明されていない可能性。
修正案: 端末外のガイドで1文だけ補足し、切替先に直前のアプリ名を表示する。
次回確認: 入力が残ることも含めて、本人が登録画面へ戻れるかを見る。

この例は仮の観察例であり、今回実際に得られたデータではない。

## 改善の優先順位

進めない・誤解する・データを失う → 必要な操作が分からない → 達成した意味が伝わらない →
単調な区間が長い → 演出の磨き込み。
何となく楽しいというAIの点数で並べず、プレイヤーの行動と課題の目的を結び付ける。
